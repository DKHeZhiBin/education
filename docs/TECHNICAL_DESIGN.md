# 数知伙伴前端技术方案

**状态：** 初稿（依据 Figma 原型；后端接口和部署环境尚未提供）  
**日期：** 2026-09-23  
**原型：** [教育类产品 Figma 原型](https://www.figma.com/proto/B0WNA5lvXXGQW6PSSWtM9k/%E6%95%99%E8%82%B2%E7%B1%BB%E4%BA%A7%E5%93%81?node-id=0-1)

## 1. 建议

采用 **React + TypeScript + Vite** 构建响应式 Web 前端，使用 **React Router** 管理页面路由，样式按基础、布局、共享组件和业务功能拆分，并用 CSS 自定义属性维护设计令牌。首个阶段聚焦把原型做成可交互的前端体验，学习数据先由本地 mock 数据驱动；接口确定后再接入服务端。

这套组合适合目前已知的范围：原型同时包含 390px 手机屏和 1440px 桌面布局，核心是登录后学习流程和仪表盘式数据展示，没有已知的公开内容 SEO、服务端渲染或后端约束。若产品确认需要公开营销页、搜索引擎收录或首屏服务端渲染，应重新评估 Next.js 或 React Router Framework Mode。

## 2. 从原型读取到的产品范围

原型名称为「数知伙伴」，定位是面向中学生的数学学习辅助产品。引导文案强调先定位卡点、再逐步帮助，不直接替学生作答。可见的主要页面和流程包括：

1. 欢迎与年级设置、学习方向选择。
2. 学习首页、开始一次学习。
3. 卡点诊断与引导式学习对话。
4. 相似题练习与练习反馈。
5. 错题本、学习进度和家长周报。

Figma 中这些流程均有手机和桌面画板。界面使用卡片、标签、进度条、学习时长柱状图和固定底部导航等模式。主色包含深青色品牌区、蓝色主要操作和青绿色辅助状态。开发时应从 Figma 变量/资产确认最终令牌，不把初步观察的颜色值当作完整设计系统。

## 3. 技术选型

| 层次 | 建议 | 用途与理由 |
| --- | --- | --- |
| UI | React | 页面由可复用的卡片、题目、标签、步骤和导航等交互组件组成。 |
| 语言 | TypeScript | 为题目、学习记录、进度和用户设置定义明确的数据形状，减少页面间传错字段。 |
| 开发/构建 | Vite | 快速启动本地开发和打包静态前端；适合当前无已知 SSR 要求的交互式应用。 |
| 路由 | React Router | 为引导、首页、练习、错题和报告提供可直达的 URL 与页面切换。初期用 Declarative/Data Router 即可。 |
| 样式 | 按功能拆分的 CSS + CSS 自定义属性 | 样式分别放在共享组件和业务功能文件中；颜色、间距、圆角、阴影和字号集中为令牌。避免在现有空目录里未经确认引入 Tailwind。 |
| 服务端数据 | 初期 mock；接口就绪后按需加入 TanStack Query | 当前没有 API 合约。数据请求、缓存、重试和失效策略等到真实接口接入时再加入。 |
| 图表 | 原生 CSS 柱状图先满足周学习时长 | 原型图表结构简单。若未来有多系列、筛选、缩放或无障碍图表需求，再评估图表库。 |
| 表单校验 | 原生约束 + 轻量字段校验 | 年级和学习方向等表单简单；复杂注册或配置流程出现后再评估 React Hook Form / Zod。 |

React 官方建议新应用优先从框架开始；其文档也说明，对框架不适合的约束或希望从基础构建时，可以从头搭建。这里暂按交互式、登录后产品和尚未确认 SSR/SEO 的情况选择 Vite。TypeScript 官方文档将其定位为 JavaScript 的静态类型检查器。参考：[React：创建 React 应用](https://react.dev/learn/creating-a-react-app)、[TypeScript 文档](https://www.typescriptlang.org/docs/)、[React Router 安装文档](https://reactrouter.com/start/framework/installation)。

## 4. 前端结构

按业务页面组织路由，通用组件按功能归类，避免一开始拆成微前端或复杂分层：

```text
src/
  app/                 # 应用入口、路由、响应式全局布局
  features/            # dashboard、onboarding、learning、review、profile 业务模块
  components/          # Button、Card、Chip、ProgressBar 等通用 UI
  services/            # API client；有接口合约后落地
  styles/              # 基础、布局、共享组件、业务功能样式和设计令牌
  main.tsx             # React 应用入口
```

初版路由建议：

```text
/onboarding
/home
/learn/new
/learn/:sessionId/diagnosis
/learn/:sessionId/coach
/learn/:sessionId/practice
/learn/:sessionId/feedback
/mistakes
/progress
```

学习流程中的会话状态（当前题目、已选答案、提示轮次、完成状态）应由 `features/learning` 管理，并通过明确的状态转换进入诊断、引导、练习和反馈阶段。初版不需要全局状态库；组件局部状态和页面级状态即可。若后续出现跨多路由的复杂持久状态，再根据实际需求评估 Zustand 等方案。

## 5. 响应式和交互实现

- **移动端优先。** 先实现 390px 画板，再扩展到桌面；桌面画板的多栏信息用断点布局呈现，避免把手机定宽画面直接放大。
- **导航适配。** 手机采用原型中的底部主导航；桌面切换为侧栏或顶栏导航，具体以桌面原型页面确认。
- **学习步骤清晰。** 诊断、提示、作答和反馈应有明确进度、返回/继续行为和空状态。
- **交互反馈一致。** 按钮、标签、答案选项提供 hover/focus/selected/disabled 状态；不能只实现静态 Figma 截图。
- **图表有文本摘要。** 周报的图形数据同时提供文字值和可读标签，色彩不作为唯一信息载体。
- **适配长内容。** 对话内容、题目解释和周报应支持自然滚动；底部导航不得遮挡操作区，并考虑安全区内边距。

## 6. 数据边界和隐私

前端领域对象可先定义 `StudentProfile`（年级、关注方向）、`LearningSession`（学习流程状态）、`Question`（题干、选项、知识点）、`AnswerAttempt`（答案、正确性、用时）、`ProgressSummary`（掌握度和学习时长）。具体字段须与后端契约对齐，不能将原型演示数字视为真实成绩。

产品涉及未成年人和学习记录。真实接入前应由产品/后端明确身份验证、家长关联、数据保留、访问控制和可删除机制。前端不应把未成年人的敏感个人信息写入 URL、日志或浏览器长期存储；题目反馈及家长报告内容也应通过授权后的接口获取。

## 7. 分阶段实现

1. **搭建骨架：** 初始化 Vite/React/TypeScript，设置路由、全局样式和响应式容器。
2. **建立视觉基础：** 从 Figma 提取颜色、字号、间距、圆角和图标资产，形成 CSS 令牌及通用组件。
3. **完成核心学习链路：** 年级引导 → 首页 → 开始学习 → 卡点诊断 → 引导练习 → 反馈。
4. **补全复习和报告：** 错题本、掌握度、学习进度与家长周报。
5. **接入真实服务：** API 合约确定后实现服务层、加载/错误/空状态和认证边界。

## 8. 暂未确定的事项

- 产品是否只面向移动端 Web，还是还要支持桌面 Web/PWA。
- 后端技术、接口契约、认证方式和部署平台。
- 学习对话是规则流程、人工内容，还是调用 AI 服务；若接入 AI，密钥和策略必须由服务端持有。
- 家长周报的数据授权、分享和隐私规则。
- 是否要求离线使用、推送、文件/图片题目上传或 SEO。

这些约束一旦确认，可能影响路由框架、缓存、身份管理和部署方式；因此本文将它们列为待定，而不是在前端阶段臆造后端设计。
