# 四级提示教学策略

## 1. 目标

提示教学 Agent 每轮只提供当前学习状态所需的最小帮助。系统使用四个递进等级，将方向、关键关系、局部操作和完整讲解分开，避免一次回复同时暴露多个后续步骤。

提示等级由服务端策略决定。模型只能在服务端提供的上下文和展示边界内组织语言，不能自行提高等级。

提示教学 Agent 不再自行选择当前解题步骤。上游 `GuidancePolicy` 先确定当前数学目标、教学状态、障碍类型、允许动作和提示等级，Agent 只执行该决策。完整状态机见 [自适应数学引导与教学状态机](../../module/教学辅导模块/ADAPTIVE_GUIDANCE.md)。

## 2. 四个等级

| 等级 | 名称 | 可以展示 | 禁止展示 | 学生下一步 |
| --- | --- | --- | --- | --- |
| 1 | `direction` 方向提示 | 应关注的条件、对象、图形区域或思考方向 | 代入后的公式、局部计算结果、答案 | 选择一个起点并说明理由 |
| 2 | `key_relation` 关键关系 | 一个定义、定理、性质、通用公式或关键变量关系 | 完成代入、连续步骤、中间计算结果、答案 | 把关系写成式子或一句推理 |
| 3 | `local_step` 局部步骤 | 推荐路线中的一个操作及其一个中间结果 | 后续步骤、完整推导、最终答案 | 独立完成紧接着的一步 |
| 4 | `full_explanation` 完整讲解 | 已校验方案的完整步骤、每步依据和最终结论 | 未校验方案、隐藏推理、超出题目的扩展结论 | 复述关键关系或完成理解检查 |

每轮 `TutorReply` 增加：

- `hint_level`：本轮实际展示的等级；
- `hint_stage`：四个英文阶段之一；
- `can_show_full_solution`：本轮策略是否允许完整讲解；
- `solution_steps[]`：只有第四级可以非空。

## 3. 等级选择

新会话以 `hint_level=0` 开始，先让学生说明题目目标和自己的起点。之后遵循以下规则：

1. 普通作答不会自动提升提示等级；没有可检查证据时先进入诊断追问；
2. 只有学生主动请求提示时，才从当前历史等级逐级提升；
3. 学生本轮已经展示后续步骤或具体误区时，服务端可以采用诊断给出的 `next_hint_level`，跳过已有证据表明无需重复的早期提示；
4. `TutoringSession.hint_level` 保存已经使用过的最高等级；
5. 学生给出新的尝试后仍可使用较低等级回应，但历史最高等级不回退；
6. 校验未通过时停止等级推进，改为请求补充条件或说明当前无法可靠确认。

## 4. 完整讲解门槛

进入第四级必须同时满足：

1. 最新 `VerificationReport.passed=true`；
2. `SolutionPlan` 存在可展示步骤；
3. 学生明确请求完整答案、完整讲解、标准解法或详细解法；
4. 学生已经提交至少一次有效尝试，或者会话已经展示过第三级局部步骤。

只有“不会”“给提示”“直接告诉我”等求助文本不算有效尝试。`LearnerState.has_meaningful_attempt` 根据本轮消息中的算式、运算符、设元、代入、展开、移项、证明关系或较完整推理描述决定，并作为会话尝试计数的唯一来源。

学生第一次直接索要答案但不满足门槛时，系统只返回下一个提示等级，不把请求本身计为尝试。

## 5. 上下文隔离

服务端按等级裁剪传给教学模型的内容：

```text
Level 1 → 知识点 + 易错点 + 突破口标题/引导问题
Level 2 → Level 1 + 一个关键关系
Level 3 → Level 1 + `next_solution_step_index` 指向的一个局部步骤
Level 4 → 完整且已经校验的 SolutionPlan
```

第三级如果解法只有一个步骤，会移除该步骤的结果，防止“局部步骤”实际等同于最终答案。

模型返回后，服务端还会检查提示正文和理解检查是否包含规范化最终答案或复制了当前定位步骤之后的已验证步骤。第三级允许简短确认学生已经完成的前置步骤和解释当前步骤，但不能继续展开后续步骤。第一级至第三级检测到越级内容时，回复会回退到对应等级的安全模板；包含多个连续步骤标记的低等级回复也会被视为疑似完整解法并回退。

## 6. 每级回复结构

每次提示只包含：

1. 一段符合当前等级的帮助；
2. 一个 `understanding_check`；
3. 等级和是否允许完整讲解的机器可读状态。

不在一轮中同时给多个新概念，也不在提示末尾附带答案作为“验证”。第四级完整讲解仍需以一个理解检查收尾，确保学生能说明关键关系，而不是只看到结果。

## 7. 降级与失败处理

- 解法未通过校验：`action=clarify`，不提供候选步骤；
- 模型不可用：使用同等级的服务端安全模板；
- 模型输出越级或包含最终答案：丢弃该文本并使用安全模板；
- 没有关键突破口：第一级使用通用方向问题，第二级要求学生写出目标与已知条件的直接关系；
- 没有可解析的局部步骤：第三级只要求完成推荐路线的第一小步，不伪造中间结果。

## 8. 后续评估指标

- 各等级越级泄露答案率；
- 学生在收到提示后的有效尝试率；
- 从一级升级到三级的平均轮数；
- 四级完整讲解触发原因；
- 已校验方案与学生可见步骤的一致性；
- 模型输出被安全模板替换的比例。

## 9. 与题库教学内容的关联

持久化结构见 [TEACHING_CONTENT_LINKS.md](../../module/题库生产与治理模块/TEACHING_CONTENT_LINKS.md)。四级提示不再只是一段运行时文本：每条提示蓝图必须绑定题目和题解，第三级必须绑定具体解法步骤；针对某类错误的提示还要绑定该步骤上的错误模式关联。

AI 生成提示先保存为 `candidate`。生产教学只能选择 `approved` 提示，第四级批准时还必须确认所绑定题解具有完整验证覆盖。运行时仍按本文件的会话门槛决定能否展示相应等级，数据库中的第四级提示不会绕过学生尝试要求。

生产检索同时要求 MySQL 关键词索引或 Qdrant payload 的 `index_status=active`、`content_status in (approved, indexed)` 且不属于评估集。题目以 `problem_pattern` 进入教学上下文；完整题解以第四级 `solution_outline` 单独存储，不能随题目结构在低等级提示中返回。Provider 返回的查询用途或提示等级若与 Orchestrator 发出的查询不一致，整份结果会被拒绝。
