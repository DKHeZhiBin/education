# 高难数学题评估集

## 目标

当前评估集用于检查多 Agent 教学链路能否正确理解高难题、形成可执行解法、给出正确答案，并如实表达验证覆盖范围。它是冻结的测试数据，不进入提示示例、RAG 索引、训练或微调数据。

## 数据来源与审核依据

第一版采用 MathOdyssey / GAIC Math 2024 的 16 道高中竞赛题。上游仓库说明，这批题由高校和中学的专业数学命题者编写，命题委员会承担命题、审核、格式检查、测试和修订工作。

- 来源仓库：https://github.com/protagolabs/odyssey-math
- 固定提交：`fe9e83df06111728e1b06ddaee0a60837c07d6c9`
- 固定源文件：`final-odyssey-math-with-levels.jsonl`
- 许可：上游新贡献采用 CC BY-SA 4.0；允许作为测试集使用，禁止作为训练集使用；题目及图片版权归原作者。

记录中的 `source_committee_reviewed` 表示继承上游委员会审核，不表示本项目已经完成第二轮人工签字。本地只做题面完整性筛查，剔除变量未定义、条件缺失或英文目标有歧义的记录，排除原因记录在 manifest 中。

任何中文翻译、条件改写或参考解答修订都会改变原审核边界。发生这些修改时，记录必须先标为 `local_review_required`，再由至少一名具备竞赛数学能力的审核者核对题干、答案和解答，并填写审核人和日期。

数据文件位于 `evals/data/high_difficulty_v1.jsonl`，manifest 位于 `evals/data/high_difficulty_v1.manifest.json`。每条记录包含固定来源、审核沿革、题目、参考答案、参考解答和评估合约。

候选题进入生产题库前必须执行隔离泄漏检查。该流程只提取评估题题面特征，拒绝把参考答案、参考题解或评估题原文写入生产存储；完整规则见 `docs/EVALUATION_LEAKAGE_DETECTION.md`。

## 隔离与防泄漏

1. 待测 Agent 只接收 `problem` 和正常产品运行时上下文。
2. `reference_answer` 与 `reference_solution` 只提供给评估器或人工裁判。
3. 评估集不得写入 RAG、相似题库、提示示例或模型训练管道。
4. Trace 中若出现上游 ID、参考解答片段或评估文件路径，本次样本标为疑似泄漏，不计入能力得分。
5. 每次运行记录模型、提示词版本、代码提交和数据集 SHA-256，保证结果可复现。

## 评估维度

| 维度 | 检查内容 | 主要证据 |
| --- | --- | --- |
| 题目理解 | 条件、目标、对象、约束和歧义是否识别完整 | `ProblemSpec` |
| 解法质量 | 路线是否成立，关键突破口是否明确，多解法是否真正不同 | `SolutionPlan` |
| 答案正确性 | 与参考答案数学等价，且满足题目定义域和边界 | 最终答案、确定性工具结果 |
| 推理完整性 | 关键步骤有依据，没有循环论证或隐含缺口 | 教学回复、Agent artifact |
| 验证诚实度 | 明确已验证、部分验证和不可程序化验证的范围 | `VerificationReport` |
| 教学策略 | 依据学生尝试逐级提示，未过早泄露完整答案 | 会话 trace、提示等级 |

代数和数论题优先使用 SymPy 或可执行计算做独立复核。几何与组合证明按照证明题覆盖规则审查；没有形式化证明时，不能仅因答案一致就标记为完全验证。

## 人工裁决流程

自动评分无法确认推理等价或证明完整性时，进入盲审：审核者先看题目和 Agent 输出并给出结论，再查看参考解答复核。裁决结果使用 `pass`、`partial`、`fail`、`invalid_case` 四档，并记录缺失条件、首个错误步骤、验证覆盖和备注。

若两个审核者结论不同，由第三位审核者只针对争议点裁决。发现源题本身有问题时使用 `invalid_case`，从汇总分母中移除，并在下一数据版本中替换；不得直接修改已经冻结的数据文件。

## 版本规则

- `v1` 文件内容冻结，manifest 保存题目 ID 和 SHA-256。
- 增删题目、翻译、修正题干或参考解答时创建新版本。
- 只补充不影响题意的评审记录时，可以保留数据版本，但必须保留审计历史。
- 构建脚本位于 `evals/build_mathodyssey_subset.py`，详细使用方式见 `evals/README.md`。
