# 首版文字题人工验收清单

最后更新：2026-10-31

## 1. 验收目标

本清单用于人工确认首版文字题学习闭环可以交付体验：学生注册并验证邮箱、登录、创建学习会话、依次获得三级提示、在满足门槛后查看完整讲解、完成学习并看到学习记录。

首版大学高数演示题使用：

```text
求 x → 0 时 (e^x − 1 − x) / x² 的极限。
```

本题正确极限为 `1/2`。本次验收至少配置一种可用的 DeepSeek 或 Gemini；模型不可用时应显示降级状态并保留题目，不把降级状态误判为完整教学验收通过。

## 3. 开始前检查

### 3.1 服务与配置

- [ ] MySQL 已启动，当前数据库已执行 `alembic upgrade head`。
- [ ] Redis 已启动，可用于认证限流、会话锁和请求幂等。
- [ ] API 已启动，访问 `GET /v1/health/live` 返回 HTTP 200。
- [ ] 访问 `GET /v1/health/ready`，MySQL、Redis 等必需项均为 `ready`。
- [ ] 前端已启动，浏览器可以打开 `http://localhost:5173`。
- [ ] 至少一种辅导模型显示可用；若模型不可用，已决定本次使用内置演示题验证降级路径。
- [ ] 记录 RAG 状态。RAG 不可用时页面应显示降级提醒，但不得阻断本演示题学习。
- [ ] 若本次需要验证 RAG 引用，Qdrant 与 Embedding 服务均已启动且就绪。

### 3.2 测试账号

- [ ] 准备一个本次验收专用的新邮箱，避免与已有账号冲突。
- [ ] 密码不少于 8 个字符，且没有写入截图、日志或本文件。
- [ ] 注册角色选择“学生”；页面不再要求选择学段或具体年级。

## 5. 三级提示内容边界

人工阅读三轮回复，并逐项确认：

### 一级：方向提示

- [ ] 只告诉学生应先观察或处理什么。
- [ ] 没有展示最终答案 `1/2`。
- [ ] 没有一次性列出完整解法。
- [ ] 页面提示等级显示为 1。

### 二级：关键关系

- [ ] 说明下一步要建立或使用的关键关系。
- [ ] 能承接学生提交的“分子前两项抵消，需要比较二阶项”。
- [ ] 没有替学生完成余下全部展开、约分和取极限过程。
- [ ] 页面提示等级显示为 2，有效尝试至少为 1。

### 三级：局部步骤

- [ ] 只演示当前需要跨过的一步。
- [ ] 没有继续展开所有后续步骤。
- [ ] 没有提前展示最终答案。
- [ ] 页面提示等级显示为 3。

### 四级：完整讲解

- [ ] 只有完成前三级引导或满足完整讲解门槛后才显示。
- [ ] 解法步骤完整、顺序清楚，并与题目条件一致。
- [ ] 最终答案为 `1/2`。
- [ ] 页面提示等级显示为 4，并展示标准解法总结。

## 6. 完整讲解门槛专项检查

该检查使用一个新的学习会话，避免受主流程状态影响。

| 编号 | 操作 | 预期结果 | 证据/备注 | 结果 |
| --- | --- | --- | --- | --- |
| G-01 | 创建相同演示题的新会话，完成诊断选择后立即点击“查看完整讲解” | 系统继续提供下一层引导，不展示完整标准解法和 `1/2` |  | ☐通过 ☐失败 |
| G-02 | 继续完成有效尝试和三级提示，再点击“查看完整讲解” | 此时允许进入四级完整讲解 |  | ☐通过 ☐失败 |

若 G-01 直接出现最终答案，本次发布验收必须判定为失败。

## 7. 完成记录与数据归属

可通过前端页面完成核心验收；需要补充证据时，可在已登录状态下查看以下接口：

- `GET /v1/auth/me`
- `GET /v1/tutoring/sessions/{session_id}`
- `GET /v1/tutoring/learning-records`

应确认：

- [ ] 会话题目、模型、状态、提示等级与页面一致。
- [ ] 会话最终状态为 `completed`。
- [ ] 学习记录包含本题题目、学生本轮作答证据、错误或卡点原因、解题路线、标签与掌握结果。
- [ ] 学习记录返回会话最终提示等级和有效尝试次数，并与本轮真实过程一致。
- [ ] 刷新浏览器或重新登录后，会话与记录仍可读取。
- [ ] 未登录请求返回 401。
- [ ] 使用另一个学生账号访问原会话返回 403 或 404，且响应不泄露原学生数据。

## 8. 恢复与降级验收

这些场景用于确认失败不会导致重复执行、丢失学生输入或误导学生。

| 编号 | 场景与操作 | 预期结果 | 证据/备注 | 结果 |
| --- | --- | --- | --- | --- |
| R-01 | 在辅导页输入一条作答，临时断开网络后点击发送 | 页面保留原作答，并显示“尚未确认送达”和重试入口 |  | ☐通过 ☐失败 |
| R-02 | 恢复网络，点击“使用同一请求重试” | 复用原 `client_turn_id`；服务端最多执行一次，本轮消息与 Agent 回复不重复 |  | ☐通过 ☐失败 |
| R-03 | 模拟 HTTP 409 `session_busy` 或 `session_version_conflict` | 页面显示明确提示，短暂等待后重新获取最新会话；可用同一请求继续重试 |  | ☐通过 ☐失败 |
| R-04 | 请求返回结构化辅导错误 | 响应包含 `code`、`message`、`retryable`；前端按 `code` 处理，不依赖中文文本匹配 |  | ☐通过 ☐失败 |
| R-05 | 使所选 LLM Provider 不可用后尝试创建或继续会话 | 页面显示模型不可用；已经输入的题目或作答仍保留 |  | ☐通过 ☐失败 |
| R-06 | 使 RAG/Qdrant 暂时不可用，使用演示题继续学习 | 页面显示“知识检索已降级”；基础教学与数学验证链路仍可继续；不得伪造来源引用 |  | ☐通过 ☐失败 |
| R-07 | 使 MySQL 或 Redis 等必需服务不可用 | 开始页显示服务暂不可用且保留题目；就绪检查明确标记未就绪 |  | ☐通过 ☐失败 |

## 9. 发布阻断条件

出现以下任一情况，首版不得判定通过：

- 注册、邮箱验证或登录无法完成。
- 学生无法创建或恢复自己的学习会话。
- 一级至三级提示提前泄露最终答案或完整解法。
- 满足门槛后仍无法查看经过验证的完整讲解。
- 演示题完整讲解给出的答案不是 `1/2`。
- 同一 `client_turn_id` 重试导致同一轮被重复执行或重复写入。
- 会话冲突后丢失学生作答，或无法重新获取最新会话。
- 完成学习后没有持久化学习记录。
- 一个学生可以读取另一个学生的会话或学习记录。
- 模型、RAG 或服务异常时清空已经输入的题目或作答。
- 辅导错误响应缺少 `code`、`message` 或 `retryable`。
