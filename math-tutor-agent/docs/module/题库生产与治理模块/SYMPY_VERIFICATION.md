# 通用 SymPy 数学验证器

## 1. SymPy 验证器是干什么的

SymPy 是一个能够对代数式、方程、极限、导数、积分、矩阵等数学对象进行符号计算的 Python 库。本系统在 SymPy 外面增加一层受控的“数学验证器”，把 Agent 给出的结构化题目和候选解答转换为可计算对象，再用确定性程序检查答案和部分解题步骤。

它主要解决以下问题：

1. **独立计算**：不采用生成 Agent 声称的答案，直接根据题目条件重新求值或求解；
2. **答案核对**：比较候选答案与独立计算结果是否数学等价；
3. **代回验证**：将候选解代回原始关系，检查等式、约束和定义域；
4. **完整性检查**：识别漏解、增解、重复解和不满足边界条件的解；
5. **步骤验证**：检查相邻结构化步骤是否等价，或者后一步是否能由前一步合法推出；
6. **生成证据**：输出机器可读的通过项、失败项、未覆盖项、版本和输入哈希，供题库准入与教学 Agent 使用。

SymPy 验证器的价值在于给模型推理增加一类可重复、可审计的确定性证据。它不是另一个解题 Agent，也不是“答案看起来合理”的语言模型复核。

## 2. 它不负责什么

SymPy 验证器不承担以下职责：

- 不从含糊的自然语言中猜测条件、变量和求解目标；
- 不判断题目在教学上是否合适；
- 不证明所有数学命题，尤其不能自动覆盖开放题和一般证明题；
- 不把“表达式无法解析”当作“答案错误”；
- 不因一次符号计算通过就直接批准或索引题目；
- 不代替独立数值验证、规则检查和 AI 教学复核；
- 不执行模型提供的任意 Python、SymPy 字符串或外部函数。

题意必须先由题意与条件检查流程整理为结构化对象。验证结果只是准入证据之一，最终内容状态仍由规则化准入门和题库状态机决定。

## 3. 通用设计

通用验证器由稳定的调度层和可扩展的题型处理器组成：

```text
SymbolicVerificationRequest
  → 能力匹配与题型路由
  → 安全数学表达式解析
  → 题型处理器构造符号模型
  → SymPy 独立计算
  → 答案、约束与步骤检查
  → SymbolicVerificationReport
```

调度层负责统一安全、版本、超时、结果状态和证据格式；题型处理器只负责本题型的数学语义。例如方程处理器定义如何构造解集，极限处理器定义趋近方向，积分处理器定义积分变量、区间和常数项比较。

这样增加题型时只注册新的能力处理器，不需要重新设计 Repository、证据对象和准入接口。

## 4. 输入契约

验证请求至少包含以下结构化信息：

| 字段 | 含义 |
| --- | --- |
| `problem_id`、`solution_id` | 被验证的题目和题解 |
| `problem_type` | 题型，用于选择能力处理器 |
| `variables` | 变量、参数及其数学类型 |
| `domain` | 实数、复数、整数、区间等定义域 |
| `assumptions` | 正值、非零、整数等显式假设 |
| `relations` | 方程、不等式、函数定义或其他规范关系 |
| `target` | 求解、化简、证明等价、求极限、求导或积分等目标 |
| `candidate_answer` | 待验证的最终答案 |
| `solution_steps` | 可选的结构化解题步骤 |
| `content_hashes` | 题目和题解内容哈希 |
| `verifier_version_id` | 本次运行采用的验证器版本 |

自然语言原题、Markdown 题解和模型隐藏推理不能直接作为 SymPy 输入。题目理解和独立解题流程必须先将其中可验证的部分转换为上述字段。

## 5. 能力声明与题型路由

每个处理器必须声明自己支持的能力，而不是仅靠类名判断：

```text
problem_types
targets
domains
supported_operators
supported_functions
supports_parameters
supports_step_equivalence
coverage_limits
```

首批可以逐步注册以下能力：

| 能力 | 典型检查 |
| --- | --- |
| 表达式等价 | 化简差值、比较规范形式、在假设下判断等价 |
| 一元及多元方程 | 独立求解、解集比较、代回、漏解和增解 |
| 方程组 | 联立求解、变量映射、解组完整性 |
| 不等式 | 解集与区间比较、端点开闭和定义域 |
| 极限 | 趋近点、左右方向、无穷行为和结果比较 |
| 导数 | 求导变量、阶数、表达式等价和定义域 |
| 积分 | 原函数求导回代、定积分上下限和积分常数 |
| 矩阵与向量 | 维度、运算结果、秩、行列式和特征值 |

表中列出的是扩展方向，不表示所有能力已经实现。没有匹配处理器时必须返回 `inconclusive`，不能退化为通用字符串比较后宣称通过。

## 6. 通用验证流程

### 6.1 输入一致性检查

运行前确认题目、题解、定义域、目标和验证器版本完整，内容哈希与加载时一致。缺少求解目标、变量冲突或内容版本已经变化时终止验证。

### 6.2 安全解析

解析器只接受白名单中的数字、符号、运算符和函数，通过受限 AST 构造 SymPy 对象。禁止使用 `eval`、不受控 `sympify`、属性访问、文件访问、网络访问和任意函数调用。

### 6.3 独立计算

题型处理器根据结构化条件自行求解、化简或计算。它不能读取生成 Agent 的隐藏推理，也不能把候选答案作为求解前提。

### 6.4 答案比较

比较方式取决于答案类型：

- 数值：精确值或声明容差内的数值一致；
- 表达式：在定义域和假设下数学等价；
- 解集：集合成员及约束完全一致；
- 区间：端点、开闭性和并交结构一致；
- 矩阵或向量：维度和对应元素一致；
- 极限、导数、积分：根据目标使用对应的符号运算复核。

### 6.5 原始条件回代

候选结果应尽量代回原始关系，而不是只代入中间整理式。回代同时检查分母非零、根式和对数定义域、区间边界、参数假设等条件，防止等价变形产生增解。

### 6.6 步骤覆盖

对于可解析的结构化步骤，验证器检查相邻步骤的等价性或蕴含关系。纯文字说明、依赖图形直觉、定理选择理由和无法安全解析的公式列为未覆盖步骤，而不是默认为通过。

## 7. 统一输出

`SymbolicVerificationReport` 应包含：

```text
status                  passed / failed / inconclusive / error
verification_level      full / partial / none
checks                   每项检查的状态、证据和失败原因
independent_result       独立计算得到的规范结果
covered_step_ids         已验证步骤
uncovered_step_ids       未验证步骤
counterexamples          可选的反例或失败代入值
assumptions_used         实际使用的定义域和假设
limitations              本次能力边界
verifier_version_id      验证器版本
input_fingerprint        规范输入指纹
duration_ms              耗时
```

四种运行状态的含义：

| 状态 | 含义 | 对自动准入的影响 |
| --- | --- | --- |
| `passed` | 本处理器声明的检查均通过 | 形成通过证据，但仍需满足其他准入条件 |
| `failed` | 得到确定性反例或不一致结果 | 阻断自动准入，模型意见不得覆盖 |
| `inconclusive` | 无匹配能力、解析失败、超时或覆盖不足 | 不视为错误，也不形成通过证据 |
| `error` | 系统、依赖或持久化异常 | 允许按策略重试，不改变内容状态 |

## 8. 验证覆盖规则

`status=passed` 和 `verification_level=full` 是两个不同概念。某一项检查通过，不表示整道题已经被完整验证。

只有同时满足以下条件时才能报告 `full`：

1. 题目目标属于已登记能力；
2. 定义域和所有阻断约束均被解析；
3. 最终答案得到独立计算和原条件回代支持；
4. 解集完整性已检查；
5. 准入规则要求覆盖的关键步骤全部被处理；
6. 没有影响结论的未验证假设。

核心答案通过但仍有重要步骤或条件无法验证时报告 `partial`。没有实质检查被执行时报告 `none`。证明题和开放题除非接入形式化证明或合格人工复核，否则不能仅凭 SymPy 获得完整覆盖。

## 9. 与其他验证手段的关系

```text
SymPy 符号验证
  + 独立数值抽样或有限穷举
  + 条件与题意检查
  + 重复及评估集泄漏检查
  + 独立 AI 教学复核
  → RuleBasedAdmissionGate
```

- 符号验证适合判断精确等价、求解和约束；
- 数值验证提供不同实现路径的第二类证据，并帮助发现符号假设遗漏；
- AI 复核负责教学标签、语言歧义和未形式化的推理，但不能覆盖确定性失败；
- 准入门汇总全部必需证据，SymPy 验证器本身不修改题目状态。

## 10. 持久化、幂等与版本

Repository 在验证前读取只读上下文，并保存题目哈希、题解哈希、状态版本和输入指纹。写入报告前重新检查内容版本；题目或题解已经变化时拒绝保存旧结果。

每次运行至少写入：

- `symbolic_verification`：独立计算、答案比较和步骤覆盖；
- `constraint_verification`：定义域、原条件回代和边界检查。

证据引用 `verifier_version_id`，并使用规范 JSON 哈希保证重复执行幂等。实现、白名单、规则或 SymPy 版本变化时创建新的验证器版本，不能覆盖旧证据。旧内容是否需要重新验证由周期复核策略决定。

## 11. 安全与资源限制

- 只允许服务端注册的数学函数和运算符；
- 限制表达式长度、AST 深度、符号数量、整数位数和多项式次数；
- 对化简、求解、积分等高成本操作分别设置超时；
- 在隔离进程或受限工作进程中执行可能产生表达式膨胀的计算；
- 不在日志中保存密钥、学生个人信息或无长度限制的原始输入；
- 超时和资源耗尽返回 `inconclusive` 或 `error`，不能返回 `passed`。

## 12. 当前实现与扩展方式

当前代码只为一元二次方程注册了完整的题型处理能力，覆盖独立求解、候选根代回、根数量、实数定义域和部分边界条件。这是通用框架的第一个处理器，不是系统最终只能验证一元二次方程。

接入新题型时应按以下顺序扩展：

1. 在题型目录中定义结构化条件、目标和答案 Schema；
2. 声明处理器能力和明确的不支持范围；
3. 实现安全的符号模型构造及独立计算；
4. 实现答案比较、原条件回代和题型特有约束；
5. 定义哪些步骤决定 `full`、`partial` 和 `none`；
6. 登记新的验证器版本；
7. 使用固定通过、失败、无结论和资源边界样例评估后再加入准入规则。
