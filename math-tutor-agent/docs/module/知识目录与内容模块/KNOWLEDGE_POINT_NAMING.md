# 知识目录与知识点命名规范

## 1. 文档目的

本规范用于维护知识目录、知识点、父子层级、先修关系以及知识点下的定义、性质、定理、公式和题型。

管理页面展示的中文名称可以调整，但系统编码会被知识星图、学习记录、先修关系、检索索引和内容引用长期使用。因此，创建编码时需要保持稳定、唯一和可读。

## 2. 名称与编码的区别

每个对象同时拥有名称和编码：

| 字段 | 面向对象 | 是否可以经常修改 | 示例 |
| --- | --- | --- | --- |
| 名称 | 学生、教师和管理员 | 可以根据教学表达调整 | 函数极限 |
| 编码 | 系统、接口和数据库 | 创建后尽量不修改 | `UC.C1.FUNC_LIMIT` |

名称可以从“函数极限”调整为“函数极限及其运算”，编码仍然保留为 `UC.C1.FUNC_LIMIT`。这样不会破坏已有学习记录、先修关系和内容引用。

## 3. 总体编码结构

知识点统一使用以下结构：

```text
课程或学段.章节.知识点.可选子知识点
```

大学高数示例：

```text
UC.C1
UC.C1.FUNC_LIMIT
UC.C1.FUNC_LIMIT.ONE_SIDED
```

各部分含义：

| 部分 | 含义 | 示例 |
| --- | --- | --- |
| `UC` | University Calculus，大学高数 | `UC` |
| `C1` | 第一章 | `C1` |
| `FUNC_LIMIT` | 函数极限 | `FUNC_LIMIT` |
| `ONE_SIDED` | 单侧极限子知识点 | `ONE_SIDED` |

## 4. 字符规则

编码必须遵守以下规则：

1. 使用英文大写字母、数字和下划线。
2. 层级之间使用英文句点 `.`。
3. 多个英文单词使用下划线 `_` 连接。
4. 编码在整个系统中必须唯一。
5. 编码开头使用稳定的课程缩写。
6. 编码中不加入空格、中文、标点或特殊符号。
7. 编码中不加入教材版本、年份和出版社。
8. 不使用无语义编号，例如 `POINT_123` 或 `ITEM_08`。

推荐：

```text
UC.C2.IMPLICIT_PARAM
UC.C3.DEFINITE_METHODS
UC.C6.SURFACE_II
```

不推荐：

```text
大学高数.第二章.隐函数
UC-2026-C2-01
POINT_123
UC.C2.隐函数求导
```

## 5. 当前课程命名空间

| 前缀 | 课程或学段 |
| --- | --- |
| `UC` | 大学高等数学 |
| `HS` | 高中数学 |
| `MS` | 初中数学 |
| `PS` | 小学数学 |

如果未来增加线性代数、概率论等独立课程，应先在本表登记新前缀。例如可以使用 `LA` 表示 Linear Algebra，但必须在正式创建数据前确定，不能在不同目录中混用多个缩写。

## 6. 大学高数章节编码

大学高数第一版使用以下章节根编码：

| 顺序 | 目录 | 根编码 |
| --- | --- | --- |
| 1 | 函数、极限与连续 | `UC.C1` |
| 2 | 一元函数微分学 | `UC.C2` |
| 3 | 一元函数积分学 | `UC.C3` |
| 4 | 向量代数和空间解析几何 | `UC.C4` |
| 5 | 多元函数微分学 | `UC.C5` |
| 6 | 多元函数积分学 | `UC.C6` |
| 7 | 无穷级数 | `UC.C7` |

根节点的父级编码必须留空。

## 7. 父级编码

父级编码表示内容分类层级，不表示学习顺序。

示例：

| 知识点 | 自身编码 | 父级编码 |
| --- | --- | --- |
| 函数、极限与连续 | `UC.C1` | 留空 |
| 函数极限 | `UC.C1.FUNC_LIMIT` | `UC.C1` |
| 单侧极限 | `UC.C1.FUNC_LIMIT.ONE_SIDED` | `UC.C1.FUNC_LIMIT` |

维护规则：

1. 根节点不填写父级编码。
2. 普通知识点通常选择本目录的根节点作为父级。
3. 只有确实需要进一步展开时才创建三级节点。
4. 不要为了视觉连线随意设置父级。
5. 父级不能指向自身或自己的子节点。
6. 移动知识点前，先确认学生端目录和星图的展示影响。

## 8. 父子关系与先修关系

这两类关系必须分别维护：

| 关系 | 回答的问题 | 示例 |
| --- | --- | --- |
| 父子关系 | 这个知识点属于哪个主题？ | 函数极限属于“函数、极限与连续” |
| 先修关系 | 学习它之前需要掌握什么？ | 学习导数前需要掌握函数极限与连续 |

一个知识点可以和父级处于同一目录，同时依赖另一个目录中的先修知识点。例如：

```text
UC.C2.DERIVATIVE
```

父级为：

```text
UC.C2
```

先修知识点可以是：

```text
UC.C1.CONTINUITY
```

## 9. 知识点层级与分类规则

当前系统使用“核心”和“基础”表示知识点在目录结构中的角色。分类由知识点所在层级决定：

| 层级 | 含义 | 分类 |
| --- | --- | --- |
| 一级 | 章节或目录根节点 | `core`，核心 |
| 二级 | 根节点下的主要知识主题 | `core`，核心 |
| 三级及更深 | 主题下可具体学习、讲解或练习的知识点 | `foundation`，基础 |

示例：

| 知识点 | 编码 | 层级 | 分类 |
| --- | --- | --- | --- |
| 函数、极限与连续 | `UC.C1` | 一级 | 核心 |
| 极限 | `UC.C1.LIMIT` | 二级 | 核心 |
| 数列极限 | `UC.C1.LIMIT.SEQ_LIMIT` | 三级 | 基础 |
| 函数极限 | `UC.C1.LIMIT.FUNC_LIMIT` | 三级 | 基础 |

维护规则：

1. 没有父级的目录根节点属于一级，分类设置为“核心”。
2. 父级为目录根节点的知识主题属于二级，分类设置为“核心”。
3. 二级主题下面的具体知识点属于三级，分类设置为“基础”。
4. 三级知识点继续拆分出的更深层节点仍设置为“基础”。
5. 调整父级导致层级变化时，应同时检查并更新分类。
6. 当前大学高数目录不使用“拓展”分类；如未来确需增加拓展模块，应先更新本规范，再录入数据。

这里的“核心”和“基础”表示目录角色，不表示题目难度，也不表示学生掌握程度。题目难度、能力要求和学习状态应由各自的数据字段维护，不能通过知识点分类代替。

## 10. 知识点名称规范

知识点名称面向学生和管理员，应满足：

1. 使用教材中常见、明确的数学名称。
2. 名称描述一个可独立学习或评估的概念。
3. 避免把多个无关知识点合并为一个名称。
4. 避免使用“其他”“补充内容”“知识点一”等模糊名称。
5. 同一目录中避免出现无法区分的重名。

推荐：

```text
函数的连续性
隐函数与参数方程求导
定积分的换元与分部积分
方向导数与梯度
```

需要拆分时，可以从二级知识点增加三级节点，不要随意改变已有稳定编码。

## 11. 内容键 `content_key`

定义、性质、定理、公式和题型中的“内容键”用于区分同一个知识点下的多条内容。

内容键规则：

1. 使用英文小写字母、数字、句点、下划线或连字符。
2. 同一知识点、同一内容类型下必须唯一。
3. 内容键表达内容含义，不使用随机编号。
4. 内容标题可以调整，内容键尽量保持不变。

示例：

| 内容类型 | 内容标题 | 内容键 |
| --- | --- | --- |
| 定义 | 函数在一点处的极限 | `limit-at-a-point` |
| 性质 | 极限的唯一性 | `limit-uniqueness` |
| 定理 | 夹逼准则 | `squeeze-theorem` |
| 公式 | 两个重要极限 | `standard-limits` |
| 题型 | 等价无穷小替换 | `equivalent-infinitesimal` |

## 12. 编码修改规则

编码创建后原则上不直接修改。

只有以下情况可以考虑修改：

- 编码拼写明显错误；
- 知识点被错误归入另一个课程命名空间；
- 上线前的数据清理，且尚无学习记录和外部引用。

已经被学生使用的知识点需要改编码时，应执行数据迁移，同时更新：

- 父子关系；
- 先修关系；
- 学习记录关联；
- 题目和题解标签；
- 检索索引；
- 缓存；
- 前端保存的链接或路由参数。

不要通过“删除旧知识点，再创建同名新知识点”的方式修改编码，这会割裂历史学习记录。

## 13. 删除与停用

管理台中的知识点删除采用安全删除：

- 节点从学生知识星图隐藏；
- 相关先修关系移除；
- 节点下内容归档；
- 历史学习记录继续保留；
- 有子知识点时禁止删除。

如果只是暂时不希望展示，应优先取消“在星图中启用”，不要删除。

目录只有在不包含任何知识点时才允许删除。

## 14. 新建知识点流程

建议按照以下步骤操作：

1. 确认所属课程和学段。
2. 选择所属目录。
3. 判断它是目录根节点、普通知识点还是子知识点。
4. 按本规范拟定唯一编码。
5. 填写清晰的中文名称和说明。
6. 设置父级知识点。
7. 设置显示顺序和启用状态。
8. 单独维护先修关系。
9. 添加定义、性质、定理、公式和题型。
10. 检查正文与公式后再发布内容。

## 15. 发布前检查清单

- [ ] 编码只包含允许的字符。
- [ ] 编码没有包含年份或教材版本。
- [ ] 编码在系统中唯一。
- [ ] 中文名称准确且面向学生可理解。
- [ ] 所属学段和目录正确。
- [ ] 父级表达内容分类，而不是学习顺序。
- [ ] 根节点的父级为空。
- [ ] 一级、二级节点分类为“核心”。
- [ ] 三级及更深节点分类为“基础”。
- [ ] 先修关系不存在循环依赖。
- [ ] 显示顺序符合课程顺序。
- [ ] 正文与公式内容已经检查。
- [ ] 未审核内容保持草稿状态。

## 16. 第一版维护约定

大学高数第一版使用 `2026.1` 目录版本。后续仅调整名称、说明、顺序、内容或先修关系时，可以继续维护当前版本。

当课程范围、章节结构或教材体系发生明显变化时，应创建新的目录版本。旧版本保留用于解释已有学习记录，不直接覆盖或删除。
